# Deferred Work

Use this file only for intentional deferrals. Every entry must name the subsystem, why it was deferred, the risk created, and what clears it.

| Title | Subsystem | Why deferred | Risk | Clears when |
| --- | --- | --- | --- | --- |
| Async destination safe-resume metadata needs durable proof | destination sync recovery | Persisted receipts, submission handles, upload locators, and destination progress are intended to prevent duplicate effects when partner idempotency is weak, but the completed-plan row remained marked unresolved. | Retry and resume paths for async destinations could silently retry without enough metadata to avoid duplicate effects. | Runtime and destination tests prove missing safe-resume metadata is a consistency failure, and stable runtime/state docs name the required receipt, submission-handle, upload-locator, polling-state, and destination-progress authority. |
| Runtime provenance query commands remain deferred | runtime provenance / operator workflows | The provenance slice added durable `runs` and `declarations` tables plus report references, but did not add public CLI commands for browsing declaration versions, comparing versions, or resetting progress scopes. | Operators can query DuckDB tables directly, but production workflows may need stable command surfaces before broad use. | `retl runs` or equivalent operator commands expose bounded run/declaration inspection, declaration-version comparison, and explicit progress reset workflows without changing automatic progress stability. |
| Calculated mapping expressions remain deferred | declaration mapping / runtime shaping | The Diff Log Runtime Reset intentionally stabilized ordered work, State/Event production, and bounded handoff before adding expression evaluation inside declarations. | Users must shape calculated fields upstream in Source SQL or upstream modeling, and connector examples cannot yet rely on RETL-owned expression evaluation. | A dedicated plan defines expression syntax, type behavior, validation errors, SQL/columnar execution boundaries, and tests without reintroducing Python row shaping. |

| Destination-specific quota scheduling remains deferred | destination retry / scheduling | Conservative in-run retries only cover short clearly retryable destination outcomes for the same planned batch.
